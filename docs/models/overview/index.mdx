## 最新模型

如果您不确定该使用哪个模型，对于大多数工作负载，建议从 [Claude Opus 5.5](/docs/models/opus-5-5/overview) 开始。对于要求较高的推理任务和长周期的 “agentic”（智能体）工作，或者当您在较高 effort 级别下对 Claude Opus 5.5 进行的 “evals”（评估）仍未达到要求时，请使用 [Claude Fable 5.2](/docs/models/fable-5-2/overview)。所有当前模型均支持文本和图像输入、文本输出、多语言能力、"vision"（视觉）以及 “tool use”（工具使用）。

* **相对延迟:** 相对于当前模型阵容进行比较。实际延迟取决于提示长度、输出长度和思考强度。
* **定价:** 每百万令牌的基础价格。Batch API 请求享受五折优惠；提示缓存读取费用为基础输入价格的 10%（Claude Fable 5.2 和 Claude Fable 5.1 为 2.5%，Claude Opus 5.5 和 Claude Sonnet 5.5 为 5%）。缓存写入、长上下文和各平台价格请参阅定价页。
* **Claude API ID:** 每个 Claude 模型 ID 都对应固定快照，包括从 4.6 代起使用的不带日期的 ID。
* **思考:** 自适应思考由模型决定思考量，并通过 effort 调节。扩展思考是早期模型上手动设置 thinking.type 为 “enabled” 并指定 budget\_tokens 的模式；该模式在 Claude Opus 4.6 和 Claude Sonnet 4.6 中已弃用，后续模型不再接受。
* **默认 effort:** Claude API 中 effort 参数的默认值。要使用其他级别，请显式设置 effort。
* **上下文窗口:** 在当前分词器（随 Claude Opus 4.7 引入）中，100 万令牌约相当于 55.5 万个单词或 250 万个 Unicode 字符；此前模型的 100 万令牌约可容纳 75 万个单词。20 万令牌约相当于 15 万个单词。
* **最大输出:** 同步 Messages API 的输出上限。在 Message Batches API 中，Claude Opus 5.5、Claude Opus 5、Claude Sonnet 5.5、Claude Sonnet 5、Claude Haiku 5.5、Claude Opus 4.8、Claude Opus 4.7、Claude Opus 4.6 和 Claude Sonnet 4.6 可通过 output-300k-2026-03-24 测试版请求头支持最多 30 万输出令牌。
* **可靠知识截止日期:** 模型知识覆盖最广泛、最可靠的截止日期。“其他详情”中的训练数据截止日期对应更广的数据范围。详情请参阅 Anthropic 透明度中心。
* **退役日期:** Anthropic 对其运营平台作出的承诺。合作伙伴运营的平台自行设定日期。
* **Claude API 别名:** 对于 4.6 代之前的模型，别名是指向带日期 ID 的便捷指针。不带日期的 ID 本身就是固定快照，别名行会重复列出这些 ID。
* **Amazon Bedrock ID:** Bedrock 的 bedrock-mantle 端点使用的 ID；若模型仅通过 bedrock-runtime 端点提供，则显示推理配置文件 ID。对于 Claude Sonnet 4.5 及后续模型，Bedrock 提供全球端点（动态路由）和区域端点（保证数据路由位置），并自行设定生命周期日期。
* **Claude Models on Google Cloud (Google managed) ID:** Claude Models on Google Cloud（Google 托管）提供全球、多区域和区域端点，并自行设定生命周期日期。
* **Microsoft Foundry ID:** Foundry 部署默认使用 Claude API 模型 ID（如有别名则使用别名）；请求中发送的是部署名称。Foundry 遵循 Claude API 的生命周期安排。
* **Claude Platform on AWS ID:** Claude Platform on AWS 使用 Claude API 模型 ID（存在别名时使用不带日期的形式），并遵循 Anthropic 自营平台的模型生命周期。

参阅[模型 ID and versioning](/docs/about-claude/models/model-ids-and-versions) and [定价](/docs/about-claude/pricing).

选定模型后，[了解如何进行您的第一次 API 调用](/docs/get-started)。要了解模型 ID、别名和快照的工作方式，请参阅[模型 ID 和版本控制](/docs/about-claude/models/model-ids-and-versions)。有关每个模型背后的可靠知识截止日期和训练数据截止日期，请参阅 Anthropic 的 [Transparency Hub](https://www.anthropic.com/transparency)。

## 使用 Models API

您可以通过 [Models API](/docs/api/models/list) 以编程方式查询模型能力和令牌限制。响应中包含每个可用模型的 [`max_input_tokens`](/docs/api/models#model_info.max_input_tokens)、[`max_tokens`](/docs/api/models#model_info.max_tokens) 以及一个 [`capabilities`](/docs/api/models#model_info.capabilities) 对象。

响应中的每个模型还有一个 [`line`](/docs/api/models#model_info.line) 字段，用于指明该模型所属的模型系列。Claude Opus 4.5 和 Claude Opus 4.6 都报告为 `opus`。使用 `line` 对模型进行分组，例如在模型选择器中。当模型不属于任何系列时，`line` 为 `null`。请读取 `line`，而不要从模型的 `id` 推断它。Anthropic 可能会添加更多系列，因此不要将这组值视为固定不变。

每个模型的 `capabilities` 对象都包含 [`thinking.types.disabled`](/docs/api/models#thinking_types.disabled)，它报告该模型是否接受 `thinking: {type: "disabled"}`，即[关闭思考](/docs/build-with-claude/thinking#turning-thinking-off)的设置。当模型以 400 错误拒绝 `"disabled"` 时，`supported` 为 `false`；对于不支持思考的模型，`supported` 为 `true`。即使 `supported` 为 `true`，API 仍可能因其他原因拒绝 `"disabled"` 请求。其中一个原因是模型在关闭思考时不允许的 [effort](/docs/build-with-claude/effort) 级别。

每个模型的 `capabilities` 对象还包含 [`thinking.types.between_tools`](/docs/api/models#thinking_types.between_tools)，它报告该模型是否接受 `thinking: {type: "between_tools"}`，即[关闭前置思考](/docs/build-with-claude/thinking#turning-thinking-off)的设置。当模型以 400 错误拒绝 `"between_tools"` 时，`supported` 为 `false`。即使 `supported` 为 `true`，API 仍可能因其他原因拒绝 `"between_tools"` 请求，例如模型在使用 `"between_tools"` 时不允许的 [effort](/docs/build-with-claude/effort) 级别。例如，对于 Claude Sonnet 5.5，Models API 报告 `thinking.types.between_tools.supported` 为 `true`，而 `thinking.types.disabled.supported` 为 `false`。

每个模型的 `capabilities` 对象还包含 [`server_tools`](/docs/api/models#model_capabilities.server_tools)，它报告该模型是否接受[网页搜索](/docs/agents-and-tools/tool-use/web-search-tool)和[代码执行](/docs/agents-and-tools/tool-use/code-execution-tool)工具。它不涵盖其他服务器工具，例如网页获取。当模型接受某个工具的至少一个版本（不一定是每个版本）时，`server_tools.web_search.supported` 和 `server_tools.code_execution.supported` 为 `true`。当模型接受这两个工具中的至少一个时，`server_tools.supported` 为 `true`。即使某个工具受支持，您组织的设置仍可能导致使用该工具的请求失败。例如，管理员可以[禁用网页搜索](/docs/agents-and-tools/tool-use/web-search-tool#how-to-use-web-search)。

顶层的 [`code_execution`](/docs/api/models#model_capabilities.code_execution) 能力是另一项不同的检查。它报告 Claude 在代码执行工具中运行的代码是否可以调用请求中的其他工具，如[编程式工具调用](/docs/agents-and-tools/tool-use/programmatic-tool-calling)中所述。例如，对于 Claude Haiku 4.5，Models API 报告 `server_tools.code_execution.supported` 为 `true`，而 `code_execution.supported` 为 `false`。

API 参考列出了"列出模型"端点的参数和完整响应。

(See the `models/list` method in [the API reference](/docs/api/models/list).)

## 提示与输出性能

当前的 Claude 模型在以下方面表现出色：

* **性能：** 在推理、编码、多语言任务、长上下文处理、诚实性和图像处理方面均达到顶级水平。有关通用及特定模型的提示指导，请参阅[提示最佳实践](/docs/build-with-claude/prompt-engineering/claude-prompting-best-practices)。
* **引人入胜的响应：** Claude 模型非常适合需要丰富、类人交互的应用程序。如果您更喜欢简洁的响应，可以调整提示，引导模型生成您想要的输出长度。详情请参阅[提示工程指南](/docs/build-with-claude/prompt-engineering)。
* **输出质量：** 从上一代模型迁移时，您可能会注意到整体性能有更大的提升。如果您使用的是 Claude Opus 5 或更早版本，请参阅 [Claude Opus 5.5 迁移指南](/docs/models/opus-5-5/migration-guide)。
